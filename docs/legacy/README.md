# Legacy documents

These are the solver half's user-facing documents as they stood before
the merge with the generator on 2026-08-28. They describe a tool called
`binsolve` that solved puzzles and did not generate them.

They are kept because they are accurate about the solver's own design
and because the reasoning in them was never rewritten, only superseded.

**For anything current, read the documents one level up:**

| Instead of | Read |

| `legacy/OPERATIONS_RUNBOOK.md` | [../OPERATIONS_RUNBOOK.md](../OPERATIONS_RUNBOOK.md) |

The phase documents that recorded the solver's decisions — its scope,
features, architecture decisions and realization plan — are **not**
legacy and stay in `docs/solve/`. They are the record of why the code is
the way it is, and the generator's equivalents live in `docs/forge/`.
